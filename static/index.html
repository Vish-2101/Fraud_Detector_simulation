SYLLABUS ALGORITHM · APRIORI

Which signals occur together?

Offline analysis · never scores
What it isApriori looks through past events for that tend to show up together.
Why it mattersSignals that co-occur can become new rules or help explain an attack. It does not score or block anything.
How to use it1) Choose which events to look at. 2) Choose how strict to be. 3) Read the found.
Glossary
Event / basket
One event and all the signals found in that event. Example: a failed signup whose basket contains “Throwaway email” and “Country mismatch”.
Signal
A simple observation that is either present or absent for one event. Example: “Repeated free trial”.
Pattern (itemset)
A set of signals that appear together often enough. Example: Shared IP + Same device, many accounts.
Support
The share of analyzed events that contain the pattern. Example: 9 of 42 events = 21%.
Confidence
For a directional rule, how often the conclusion appears when the premise appears. Example: 6 of 6 Shared IP events also had Same device, many accounts = 100%.
Lift
How many times more often the signals co-occur than chance. Example: 4.2× means 4.2 times more often than chance.
Prevalence
The share of analyzed events labelled abuse. Example: 27 of 42 events = 64%. Labels are evaluation-only.
Candidate
A combination Apriori checks against the event baskets. Example: the pair Shared IP + Failed payment.
Pruning
Skipping combinations that contain a rare signal, because the whole combination must be rare too. Example: a rare signal cannot form a frequent triple.

How Apriori found these

    Apriori skips any combination containing a rare signal, because the whole combination must be rare too. That is the pruning that keeps this fast.

    Do the patterns hold up later?

    We find patterns in the first half of the events, then check whether they still hold in the second half.

    waiting for events

    ✓ Holds up↘ Does not hold up? Not enough data

    “Not enough data” means the pattern’s premise never appeared in the second half, so its later confidence cannot be measured.

    Advanced (evaluation only)
    These patterns include the abuse label, so they are for checking the data, never for scoring. Patterns built from rules can be circular: a pattern may simply restate a rule we already use.

    Advantages / Limitations

    offline only

    Advantages

    • Patterns are readable: they name signals that show up together.
    • Pruning keeps the search tractable for small event baskets.
    • Useful for hypotheses and for explaining which signals cluster.

    Limitations

    • Co-occurrence is not causation and is not a risk score.
    • Support can hide rare abuse in imbalanced data.
    • Baskets are rule-derived, so patterns can be circular; this is offline only.

    flip counts when removed

    A flip means removing that rule changes review/block to another action on the temporal test split. Counts of 0 are honest: many rules overlap or never fire on a dataset.
