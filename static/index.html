Possibly seen before?

Insert-only means expiry of exact counters does not delete bits. The optional rotating mode keeps the old generation for queries and starts a new one for inserts, so the filter can forget. A positive is never proof: the scoring rule requires corroboration and adds at most +10.

Advantages / Limitations

Advantages

  • O(m) bits regardless of how many identifiers are remembered; O(k) query/insert.
  • No false negatives for inserted keys; deterministic keyed BLAKE2b hashing.
  • Good fit for “has this bad identifier been seen?” with a privacy-friendly footprint.

Limitations

  • False positives; positive ≠ proof of fraud.
  • Insert-only cannot remove an identifier unless a rotating generation forgets it.
  • Decision feedback can reinforce past flags; bounded here by a corroboration requirement.
  • Missing/rotated device identifiers limit what can be remembered.
SYLLABUS ALGORITHM · DGIM

Count suspicious 1s without storing the window.

In fraud detection: each device/card stream carries a binary suspicious bit (failure, disposable/forwarding email, country proxy). DGIM estimates how many 1s are in the last N events using O(log²N) buckets.

One-click demo: run the 1000-element stream, then the worst-case pattern, and compare bucket storage with exact storage.

Live buckets

most recent device

Run a scenario to populate DGIM streams.

Each box is a bucket; width grows with bucket size. At most two buckets of each power of two. Estimate = sum(sizes) − oldest(size)/2, so the relative error bound is ≤ ~50%.

Estimate vs exact

—
Run the scale demo to plot the estimate against the exact count.

Memory-bounded replay: per-entity streams are capped with an LRU (512 streams by default), so replaying 50k+ events does not grow without bound.

Advantages / Limitations

Advantages

  • Sublinear storage: O(log²N) buckets for a window of N bits.
  • Streaming updates are amortized O(log N); no need to keep every event.
  • Works well for bursts where exact per-entity counters are too expensive.

Limitations

  • Approximate: the classical bound is ~50% relative error, not exact.
  • Count-based window, not event-time; it is only “60 seconds” when events arrive at 1/s.
  • The suspicious bit is a proxy definition; it can miss label-bearing context.
  • Contributes modest points and cannot block alone.
SYLLABUS ALGORITHM · APRIORI

Which signals occur together?

In fraud detection: level-wise frequent-itemset mining over per-event signal baskets surfaces combinations like card velocity + failure + mismatch. It is offline analysis and never scores an event.

One-click demo: run mixed traffic, lower support to the auto-suggested value for imbalanced data, then compare all baskets with the fraud-only subset.

Circular-pattern warning: baskets are rule-derived, and labels only appear in the offline evaluation mode or as a subset selector. High support or lift is not causation; a stable time-split check is stronger evidence than a single-session pattern.

Advantages / Limitations

Advantages

  • Interpretable itemsets and rules with support, confidence and lift.
  • Subset pruning makes the level-wise candidate search tractable for small baskets.
  • Useful for hypothesis generation and for explaining co-occurring signals.

Limitations

  • Frequent co-occurrence is not causation and not a calibrated risk score.
  • Support hides rare fraud patterns in imbalanced data; the auto-suggest and fraud-only view help.
  • Baskets come from the same rules, so patterns can be circular.
  • Offline only; cost grows with item vocabulary and basket count.

What the numbers mean

  • Positive = review or block under the current review threshold.
  • PR-AUC is average precision over the held-out test split.
  • Recall@FPR is the best recall at or below that false-positive rate.

Limitations

  • Labels are authored for teaching, so results demonstrate mechanics, not real-world fraud rates.
  • The fixture is small and synthetic; one split is not a production estimate.
  • Proxy signals and approximate algorithms are documented in the README.
